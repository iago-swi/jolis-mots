# Jolis Mots 1.0.3 : saisie rapide, vérificateur, orthographe, historique complet sous Windows

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aider Philippe à nettoyer et compléter ses mots dans l'atelier : une saisie plus rapide, un vérificateur de cohérence, l'orthographe en français, et l'historique complet de la liste sous Windows.

**Architecture:** La logique (abréviations, vérification, historique d'une suite de listes) va dans `packages/core`, testée. L'atelier (`apps/web`) l'affiche. Le processus principal d'Electron règle le correcteur et lit l'histoire de la branche `donnees` dans la copie locale, par le pont.

**Tech Stack:** celui de la 1.0.2 (TypeScript, Svelte 5, Vite, Vitest, Electron 45.4.1, git du système).

**Spec:** `docs/superpowers/specs/2026-11-24-jolis-mots-design.md`, section 15 (et 14 pour les règles de l'historique).

## Global Constraints

- Tout en français ; l'application tutoie ; espace fine insécable (U+202F) avant « ? », « ! », « ; », « : » dans les textes de l'application.
- **Le texte saisi fait référence.** Aucune correction n'est appliquée sans un clic de Philippe ; le vérificateur ne fait que signaler.
- **Rien n'est envoyé sur la vraie branche `donnees`.** Tout essai du bureau pose `JOLISMOTS_DEPOT` (dépôt nu local) et `JOLISMOTS_DONNEES` (dossier temporaire). Ne jamais toucher `%APPDATA%\Jolis Mots`, ni arrêter une « Jolis Mots.exe » en cours.
- Couleurs : seulement `--papier`, `--encre`, `--second`, `--filet`, `--exemple`, `--accent`. Sobre.
- Branche `release/jolis-mots-v1.0.3` ; un commit par tâche, message simple en français, sans ligne d'attribution ; ni push ni étiquette.
- Après chaque tâche, `npm test` et `npm run check` passent.

## Review Focus

1. Tab dans la définition ne doit jamais avaler du texte : seul le mot collé au curseur est remplacé, et seulement s'il est une abréviation connue.
2. Une correction proposée ne touche que ce qu'elle annonce (aucun autre caractère de la définition ne change).
3. Le vérificateur ne doit pas noyer Philippe : sur la liste réelle (1 137 mots complets), le nombre de mots « À vérifier » est raisonnable et les remarques sont justes ; mesurer et le dire.
4. L'historique lu sur GitHub reste juste si une version de `mots.json` dans l'histoire est illisible (elle est sautée) et ne bloque pas l'écran (lecture en arrière-plan, repli sur l'historique local).
5. Le correcteur en français et la liste des mots inconnus fonctionnent dans l'application empaquetée, pas seulement en développement.

### Task 1: Cœur : abréviations et vérificateur

**Files:** Create `packages/core/src/saisie.ts`, `packages/core/src/verification.ts` and their tests; modify `packages/core/src/index.ts`.

**Interfaces (produces):**

```ts
// saisie.ts
export const ABREVIATIONS_SAISIE: Readonly<Record<string, string>>; // la table de la section 15.2, sauf `n`
export const BOUTONS_SAISIE: readonly { texte: string; abreviation: string; principal: boolean }[]; // l'ordre de la barre ; principal = visible sans « ⋯ » (`1.`, [Litt.], [Fig.], [Par ext.], [Vieux], [Fam.], EX:, SYN:, US:)
export function developper(avant: string): { longueur: number; insertion: string } | null;
// `avant` = le texte de la définition jusqu'au curseur. Si le mot collé au curseur (lettres seulement, précédé d'un début de texte, d'une espace ou d'un retour à la ligne) est une abréviation (sans tenir compte des majuscules), rend combien de caractères retirer et quoi insérer. `n` : « \n» suivi du numéro suivant le plus grand numéro de sens déjà présent avant le curseur (1 s'il n'y en a pas) et « . » ; sans retour à la ligne si le curseur est en début de ligne. Sinon null.
export function numeroSuivant(avant: string): number;

// verification.ts
export type CodeRemarque = 'balise' | 'indication-inconnue' | 'indication-hors-crochets' | 'numerotation' | 'non-ferme' | 'exemple-vide' | 'genre-vide' | 'genre-inconnu' | 'espaces';
export interface Remarque { code: CodeRemarque; texte: string; correction: string | null } // correction = la définition corrigée, ou null si rien de mécanique
export function indicationsConnues(mots: Mot[]): Set<string>; // celles de la table de definition.ts (développées ou non) + toutes celles employées par au moins deux mots complets ; comparées en minuscules
export function verifierMot(m: Mot, connues: Set<string>): Remarque[];
export function corrigerEspaces(texte: string): string; // espaces doubles → une, espace avant . ou , retirée ; ne touche pas aux retours à la ligne
export function corrigerBalises(texte: string): string; // `EX :`, `Ex:`, `ex:`, `Syn :`… → forme canonique `EX:` ; rien d'autre
```

Règles de `verifierMot` (textes exacts à écrire en français, une phrase courte chacun, avec U+202F avant « : ») : celles de la section 15.3, sauf l'orthographe (tâche 3). « Indication hors crochets » : en tête d'un sens, `Sens figuré`, `Au fig.`, `Fig.`, `Par ext.`, `Litt.`, `Vieilli`, `Vieux` sans crochets, ou un mot entièrement en minuscules suivi d'un mot qui commence par une majuscule (« fauconnerie Oiseau »). Numérotation : les numéros en tête de ligne doivent valoir 1, 2, 3… dans l'ordre. Non fermé : compte de `[`/`]`, `(`/`)`, `«`/`»` différent. Un mot « à compléter » n'est pas vérifié (rend `[]`).

- [ ] Tests d'abord (RED consigné) : chaque abréviation de la table ; majuscules ignorées ; `exemple` + Tab ne fait rien ; abréviation au milieu d'un mot (`texte`) ne fait rien ; `n` après « 1. … » donne « \n2. » ; `n` en début de ligne donne « 2. » ; chaque code de remarque sur un exemple tiré de la vraie liste (Béjaune : « fauconnerie Oiseau », genre vide) ; `corrigerBalises` et `corrigerEspaces` ne changent aucun autre caractère (comparer caractère par caractère hors zone corrigée) ; pureté.
- [ ] Mesure sur `donnees/mots.json` (lecture seule) : nombre de mots complets avec au moins une remarque, par code. Le consigner dans le compte rendu.
- [ ] Commit : « Atelier : abréviations et vérificateur, sans interface »

### Task 2: Atelier : barre, Tab, filtre « À vérifier »

**Files:** `apps/web/src/composants/atelier/FicheAtelier.svelte`, `ListeMots.svelte`, `apps/web/src/atelier.svelte.ts` (+ tests), `packages/core/src/atelier.ts` (+ tests).

- `FiltreAtelier` gagne `'aVerifier'` ; `compterFiltres` / `listerAtelier` prennent en option une fonction `aVerifier(m: Mot): boolean` (sans elle, le filtre est vide) — le cœur ne connaît pas l'orthographe ni les remarques ignorées.
- Atelier (classe) : `remarques(m: Mot): Remarque[]` (vérification + orthographe quand elle est connue, sans les ignorées) ; `ignorer(id, code)` gardé dans `localStorage` sous `jolismots.verification.ignorees.v1` (liste de `id:code`) ; `corriger(code)` applique la correction au brouillon (le brouillon devient modifié, rien n'est enregistré sans « Enregistrer »). Les connues (`indicationsConnues`) sont dérivées une fois par liste.
- Fiche : la barre au-dessus de la zone de définition (boutons de `BOUTONS_SAISIE`, « ⋯ » qui déplie les autres, `title` = « Abréviation : litt, puis Tab ») ; un clic insère au curseur avec `document.execCommand('insertText', …)` pour garder Ctrl+Z, puis rend le curseur à la zone ; Tab dans la définition appelle `developper` et, si non null, sélectionne les `longueur` caractères avant le curseur et insère `insertion` de la même façon (`preventDefault`) ; sinon Tab reste normal. Au-dessus de la barre, les remarques du mot : texte en encre secondaire, petit ; « Corriger » quand `correction` n'est pas null ; « C'est voulu ».
- Liste : le filtre « À vérifier » avec son nombre, entre « À compléter » et « Doublons ».
- [ ] Tests d'abord pour la classe (ignorer persistant, corriger ne touche que le brouillon, filtre) et le cœur (filtre).
- [ ] Vérification au navigateur (`?pont=demo#atelier`, 1280 × 800 et 1000 × 700, Papier et Nuit) : barre, Tab, Ctrl+Z après un développement, remarques de « Béjaune », Corriger, C'est voulu, le filtre ; la rangée d'actions de la fiche reste visible. Captures dans le dossier de travail.
- [ ] Commit : « Atelier : barre d'abréviations, Tab, filtre À vérifier »

**Files:** `apps/desktop/src/main.ts`, `apps/desktop/src/preload.ts`, `apps/desktop/src/depot.ts` (+ tests), `packages/core/src/pont.ts`, `packages/core/src/historique.ts` (+ tests), `apps/web/src/pont-demo.ts`, `apps/web/src/atelier.svelte.ts` (+ tests), `apps/web/src/ecrans/Historique.svelte`.

Le pont gagne `historique(): Promise<EntreeHistorique[] | null>` (null si pas de copie ou en cas d'échec). `Historique.svelte`, sur bureau, demande cet historique à l'ouverture et l'affiche ; en attendant ou sur null, il montre l'historique local.
